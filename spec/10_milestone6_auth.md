# Milestone 6 — аутентификация: Google, GitHub, email+пароль

> Дата: 2026-06-11. Самодостаточная веха, не пересекается с моделью коробок/дат.
> Решение: использовать django-allauth (НЕ писать аутентификацию с нуля).

## Почему allauth, а не с нуля
Аутентификация — зона, где "с нуля" создаёт дыры в безопасности (хеширование, защита от
перебора, сброс пароля, OAuth state/CSRF, верификация email). django-allauth — стандартное
зрелое решение для Django: один пакет покрывает все три способа входа сразу, включает
защиту от перечисления пользователей и проверенные OAuth-флоу.

## Стек (важно для нашего случая)
- **Чистый django-allauth на СЕССИЯХ.** У нас MPA (Django-шаблоны + HTMX), НЕ SPA.
- НЕ использовать dj-rest-auth / JWT / DRF — это для API/SPA-фронтендов, нам не нужно.
- client_id/secret провайдеров (Google, GitHub) — через Django admin (Social Applications),
  НЕ хардкодить в settings.py.

## Три способа входа (BR-AUTH)
1. **Email + пароль** — регистрация, вход, сброс пароля (через allauth account).
2. **Google** — OAuth (allauth.socialaccount, провайдер google).
3. **GitHub** — OAuth (провайдер github).

## Связывание аккаунтов (важно — без дублей)
- Вход через Google/GitHub: если email НОВЫЙ → создать аккаунт, верификацию пропустить
  (провайдер уже подтвердил email); если email СУЩЕСТВУЕТ → войти в существующий аккаунт,
  не плодя дубль.
- Соц-аккаунтам присваивается сгенерированный безопасный пароль; через сброс пароля
  пользователь может задать обычный. Оба способа ведут к ОДНИМ данным.

## Решения по умолчанию (можно поменять)
- **Верификация email: ОПЦИОНАЛЬНАЯ** (ACCOUNT_EMAIL_VERIFICATION='optional'). Проще
  стартовать; ужесточение до 'mandatory' — одна строка конфига позже.
- **Существующий вход** (текущий signup/login по email) — МИГРИРОВАТЬ на allauth, не держать
  второй механизм рядом. Перенести существующих пользователей (они уже Django User).

## Изменения
- Зависимости: django-allauth (+ нужные провайдеры). settings: INSTALLED_APPS (allauth,
  allauth.account, allauth.socialaccount, провайдеры, django.contrib.sites), SITE_ID,
  бэкенды аутентификации, SOCIALACCOUNT_PROVIDERS (scope google: profile/email; github: user:email).
- urls: подключить allauth urls.
- Шаблоны: переопределить templates/account/login.html и signup под наш дизайн (Tailwind-токены).
- Миграция: применить миграции allauth; перенести/сохранить текущих пользователей.

## Out of scope
- Мультиаккаунты в смысле Android AccountManager (это про другое, остаётся вне области).
- 2FA, SAML/SSO, enterprise — не сейчас.
- JWT/API-аутентификация — пока нет SPA, не актуально.

## Тесты
- Регистрация и вход по email+паролю; сброс пароля.
- Вход через Google и GitHub (можно мокать провайдер).
- Связывание: вход через провайдера с существующим email не создаёт дубль.
