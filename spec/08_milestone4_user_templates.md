# Milestone 4 — пользовательские шаблоны целей

> Дата: 2026-06-11. Открыт после milestone 3.
> Контекст: сейчас шаблоны read-only (засеяны, только потребляются — подтверждено КК).
> Цель вехи: пользователь САМ создаёт, редактирует и удаляет шаблоны целей.

## Решения по объёму (зафиксированы с пользователем)
1. **Только редактор с нуля.** Пользователь создаёт шаблон руками: задаёт заголовок/описание,
   добавляет майлстоуны, внутри них — задачи шаблона. Конвертация "сохранить существующую
   цель как шаблон" — НЕ в этой вехе (возможно позже).
2. **Все шаблоны пользовательские.** Шаблон принадлежит владельцу (`owner`). Системный сид
   шаблонов УБИРАЕТСЯ. Один предопределённый шаблон из сида вернём ОТДЕЛЬНО, позже.
3. **Без дельта-дней в редакторе.** Пользователь задаёт СТРУКТУРУ (майлстоуны + задачи),
   НЕ возится со смещениями `*Days` (решение milestone 3: майлстоунов достаточно).
   Поля `*Days` в модели остаются, но в редакторе шаблона не выставляются.

## Правила

### BR-26: Владение шаблонами
- `GoalTemplate` получает владельца (`owner` → User). Запросы шаблонов owner-scoped (BR-6).
- Пользователь видит и управляет ТОЛЬКО своими шаблонами.
- Прежний глобальный/системный сид шаблонов убрать (или пометить как пользовательские при
  миграции — на усмотрение реализации, но в UI всё под владельцем).

### BR-27: CRUD шаблона целей
- **Create**: форма нового шаблона — заголовок, описание (опц.). Создаётся пустым.
- **Read**: список своих шаблонов + просмотр содержимого (как уже есть каталог, но scoped).
- **Update**: правка заголовка/описания.
- **Delete**: удаление шаблона со всем содержимым (майлстоуны/задачи/KeyResults каскадом).

### BR-28: CRUD содержимого шаблона
Внутри открытого шаблона:
- **Майлстоуны**: добавить / переименовать / удалить / упорядочить (по `index`).
- **Задачи шаблона** внутри майлстоуна: добавить / редактировать (заголовок, заметка,
  чек-лист, повтор) / удалить. Привязка к майлстоуну (`milestoneId`).
- **KeyResults** (опц. в рамках вехи): если включаем — заголовок, тип (SIMPLE/SUM/LAST),
  плановое значение. Можно вынести во вторую фазу вехи, если объём велик.
- Даты задач шаблона: НЕ через дельта-дни в UI (см. решение 3). Если нужны относительные
  сроки — отдельное будущее решение.

### BR-29: Применение пользовательского шаблона
- "Создать цель из шаблона" работает с пользовательскими шаблонами так же, как раньше
  с системными (существующий механизм createGoalFromTemplate сохраняется).

### BR-T1: Снять блокировку редактирования задач из шаблона
ОТМЕНЯЕТ прежнее поведение BLOCKED_BY_GOAL_TEMPLATE (задачи из шаблона были заблокированы,
403 на update, read-only редактор).
- Причина отмены: блокировка имела смысл в оригинале MaxDone из-за ПУБЛИЧНОГО каталога
  шаблонов (связь задачи с опубликованным источником). В single-user, где шаблоны свои,
  запрет редактировать собственные задачи бессмыслен и мешает.
- Новое поведение: задача, созданная из шаблона — ОБЫЧНАЯ редактируемая задача. Никакого
  403, редактор полнофункционален.
- Пометку происхождения ("из шаблона X") можно сохранить для истории, но БЕЗ запрета
  редактирования. Не обязательно в рамках вехи.
- Убрать логику блокировки (флаг/проверку 403/read-only editor), обновить затронутые тесты
  (тест на 403 теперь должен проверять ОБРАТНОЕ — задача редактируема).


## Изменения БД
- `GoalTemplate.owner` — НОВОЕ поле (FK User). Требуется миграция.
- Возможен дроп/переразметка сид-данных шаблонов (они были без владельца).
- Остальная структура (milestone/task/keyresult templates) уже есть — менять не требуется.

## Out of scope для Milestone 4
- "Сохранить цель как шаблон" (конвертация) — позже.
- Публичный каталог / шаринг шаблонов / авторство с публикацией (как в оригинале MaxDone:
  DRAFT/PUBLISHED, creator-поля, счётчик использований) — НЕ делаем, это single-user.
- Один предопределённый шаблон из сида — ОТДЕЛЬНЫЙ шаг после этой вехи.
- Дельта-дни в редакторе.

## Тесты (ожидаемые)
- Создание/правка/удаление шаблона owner-scoped; чужой шаблон недоступен (BR-6).
- CRUD майлстоунов и задач шаблона; каскадное удаление.
- Применение пользовательского шаблона → создаётся цель с майлстоунами и задачами.
