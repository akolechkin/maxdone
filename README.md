# maxdone (Django + HTMX + Tailwind)

Функциональный аналог MaxDone. Доменная модель, горизонты и фичи восстановлены
из декомпилированного APK (см. `spec/`); реализация собственная.

## Запуск (одна команда, без шага сборки CSS)

```bash
docker compose up web
```

Открой http://localhost:8000 — логин **demo / demo** (данные засеяны автоматически).
Админка: http://localhost:8000/admin — **admin / admin**.

Стили подключены через Tailwind Play CDN, поэтому отдельная сборка не нужна.
Для продакшена собери CSS и убери CDN (см. tailwind.config.js + theme/input.css).

## Что работает (полный функционал)
- **Задачи**: создание, редактирование, удаление, завершение.
- **Даты**: срок, начало, «скрыть до» (datetime-local), повтор (RRULE-строка).
- **Горизонты**: TODAY/WEEK/LATER/INBOX со счётчиками; перемещение задачи
  между горизонтами (кнопки при наведении).
- **Скрытие**: задача со «скрыть до» в будущем уходит в HIDDEN и возвращается
  по дате (BR-1).
- **Чек-листы**: добавление/переключение/удаление пунктов (HTMX, без перезагрузки).
- **Цели**: список, создание, редактирование, удаление (PRIVATE/CORPORATE, статус, периоды).
- **Контексты**: список, создание, удаление; выбор при редактировании задачи.
- **Поиск**: по задачам и целям (живой, debounce).
- **Приоритет**: дробный ранг, авто при создании (BR-4).
- **Изоляция владельца** (BR-6) — везде.

## Тесты
```bash
docker compose exec web python manage.py test
```
Покрывают: видимость/скрытие (BR-1), счётчики (BR-2), завершение (BR-3),
приоритет (BR-4), изоляцию (BR-6), enum-контракт из APK, и CRUD/move/search.

## Архитектура
MPA + HTMX (фрагменты вместо JSON-API), Alpine для UI-состояния панелей,
Tailwind-токены MaxDone. Бизнес-логика — в `tasks/services.py`.

## Spec-driven цикл
Источник истины — `spec/`. Правила в `CLAUDE.md` и `WORKFLOW.md`.
Каталог всех фич оригинала — `spec/04_feature_catalog.md` (помечено, что
реализовано, что кандидат на спеку, что Android-специфично).
